# Demo GIF

`docs/demo/taste.gif` is a recording of the README's console block at 80
columns. `docs/demo/taste.tape` is the [VHS](https://github.com/charmbracelet/vhs)
script that produces it. Both are checked in. The GIF is regenerated by hand,
never in CI and never by the test suite.

A test (`tests/docs/test_demo_tape.py`) fails if the commands the tape types
while shown differ from the README block in text or order. It reads the tape
only; it does not render it. After editing the block, edit the tape's visible
`Type` lines to match, then regenerate.

## Tools

vhs, ttyd and ffmpeg are system tools, not Python dependencies. vhs also needs
a Chromium, which it downloads on first run.

- vhs: <https://github.com/charmbracelet/vhs#installation>
- ttyd: <https://github.com/tsl0922/ttyd#installation>
- ffmpeg: from your package manager

## Regenerate

From the repository root, with the dev environment synced (`uv sync`):

```sh
vhs docs/demo/taste.tape
```

The tape's hidden prelude activates `.venv`, builds the docs sample home into a
temporary directory with `python -m tests.docs.sample`, points `HOME` and the
XDG directories at it and sets `COLUMNS=80`. The recording therefore shows the
same output the checker verifies, with a bare `$ ` prompt and no user name,
host or path.

## Before committing

Open the first and last frames and look for a leaked path, user name or host:

```sh
ffmpeg -i docs/demo/taste.gif -vf "select=eq(n\,0)" -frames:v 1 first.png
ffmpeg -sseof -1 -i docs/demo/taste.gif -frames:v 1 -update 1 last.png
```

Then check the diff of `README.md` still embeds `docs/demo/taste.gif`.
