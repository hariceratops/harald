# Demo GIF

`docs/demo/taste.gif` is a recording of the README's console block at 80
columns. `docs/demo/taste.tape` is the [VHS](https://github.com/charmbracelet/vhs)
script that produces it. `docs/demo/tui.gif` and `docs/demo/tui.tape` record
the TUI the same way: lookup, the entry and all tenses. `docs/demo/study.gif`
and `docs/demo/study.tape` add the noun `Hund` as cards and study both. All six
are checked in. The GIFs are regenerated by hand, never in CI and never by the
test suite.

A test (`tests/docs/test_demo_tape.py`) fails if the commands the taste tape
types while shown differ from the README block in text or order. After editing
the block, edit the tape's visible `Type` lines to match, then regenerate.

The same file checks both TUI tapes: each must launch `harald`, and every
single key it types while shown must be in the guide's home, lookup, entry,
add-word or study key table. After changing those tables or the TUI flow,
adjust the tapes. The tests read the tapes only; they do not render them.

## Tools

vhs, ttyd and ffmpeg are system tools, not Python dependencies. vhs also needs
a Chromium, which it downloads on first run.

- vhs: <https://github.com/charmbracelet/vhs#installation>
- ttyd: <https://github.com/tsl0922/ttyd#installation>
- ffmpeg: from your package manager

## Regenerate

From the repository root, with the dev environment synced (`uv sync`):

```sh
vhs docs/demo/taste.tape
vhs docs/demo/tui.tape
vhs docs/demo/study.tape
```

The tape's hidden prelude activates `.venv`, builds the docs sample home into a
temporary directory with `python -m tests.docs.sample`, points `HOME` and the
XDG directories at it and sets `COLUMNS=80`. The recording therefore shows the
same output the checker verifies, with a bare `$ ` prompt and no user name,
host or path. The TUI tapes use the same prelude and take about a minute each.
The study tape relies on the sample home having a German noun (`Hund`).

## Before committing

Open the first and last frames and look for a leaked path, user name or host:

```sh
ffmpeg -i docs/demo/taste.gif -vf "select=eq(n\,0)" -frames:v 1 first.png
ffmpeg -sseof -1 -i docs/demo/taste.gif -frames:v 1 -update 1 last.png
```

Repeat for `tui.gif` and `study.gif`, then check the diff of `README.md` still
embeds all three GIFs.
